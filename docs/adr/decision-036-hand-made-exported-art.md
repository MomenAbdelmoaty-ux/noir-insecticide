# decision-036: Art is hand-made in an editor and exported as single transparent images

**Status:** Accepted
**Date:** October 30, 2026

## Context

The art style is flat two-tone shapes broken into disconnected floating shards. The first plan was shard definitions in data and a renderer that draws each thing whole and then shatters it, with a budget of 8 shards per entity.

## Decision

Weapons, enemies, and traps are drawn by hand in an editor with their shards in place, and exported as one image each with a transparent background. There is no shard rendering or shattering code. Enemies and traps have their dotted outline baked into the art, as a dotted stroke in the inverse color, with a version for each color the thing exists in (Black, White, or Gray). Player-owned things have no outline. Weapons are single static sprites. Rotating, flipping, scaling, and moving a sprite by code are allowed. Animation that changes how a sprite looks is planned after version 0.2.0. Until Milestone E the game uses placeholder art.

## Consequences

Rendering is simpler and faster, and the images pack into texture atlases. The 8-shard budget (quality-004) is removed. Each new enemy or trap needs a hand-made image in each color it exists in. The number of images is small for now. Code that traces the edge of an image is not built, and can be revisited if enemy types multiply or bugs are generated by code. The dots are drawn at the 64-pixel art scale (decision-035).

## Alternatives considered

- Shard definitions and a renderer that shatters each thing at run time: more code and more to budget and measure.
- Tracing the outline by code when the game loads: a few hours of work, and not needed while the number of images is small.
- Animated weapon sprites: planned after version 0.2.0.
